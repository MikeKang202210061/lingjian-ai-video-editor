# 影像探索纪实

采用参考影视飓风公开制作实践的原创配方。不要宣称作者授权、官方出品或逐镜复刻。

## 分析素材

先找建立空间的远景、行动中景、工艺细节、人物反应和可听见的现场声。
依据实有素材标注地点建立、目标、推进、障碍、发现和回望；不凭空补航拍、慢动作或危险经历。
保留前因后果、动作方向、环境变化及完成任务所需的过程证据。
抽帧不代表连续视频；不能因某帧看起来平静就认定整段稳定，也不能猜测对白位置。

## 编排镜头

优先用环境和真实目标建立方向，随行动交替使用远、中、近景，再展示发现和人物反应。
建议动作细节约 2–4 秒，环境/反应约 4–8 秒；让完整动作和声音决定切点，避免机械卡点。
在候选 JSON 的 reason 中解释镜头如何建立空间、推进过程或支撑发现，不增加接口未声明字段。
保留拍摄顺序锁与原素材边界。缺少环境镜头时利用现有中景交代，不假装生成过航拍。
把地点、时间、测量和结论限制在素材或用户提供的事实内；没有可定位转写时字幕留空。

## 安排效果与声音

普通切点保持干净，保留现场原声；用低音量配乐衬托，避免每次转场都加 whoosh。
在发现或结尾处至多每 16 秒安排一次克制慢推；已有字幕采用简洁强调，避免连续弹跳标题。
默认不增加装饰提示音；不要把现有旁白、风声或动作声描述为新合成的声音桥。
保持自然饱和度。轻量 CDL 只作为起点，不能修复曝光、白平衡或 Log 色彩管理，也不等同作者调色。
仅在素材本身具备时利用慢动作、航拍或摄影测量；把速度变化、三维路线、跟踪合成列为待制作项。

## 执行与审阅

使用 [profile.json](profile.json) 的受限配方，由灵剪编译本地效果与 Resolve 指令。
Resolve 当前映射静态缩放和轻量饱和度；不把它们称作动态推镜、完整声音设计或 Fusion 合成。
禁止生成或执行任意 Python、Shell、SDK 方法名和外部模板路径。
展示镜头依据、执行能力及素材缺口，等待用户应用；保持现有预览、校验和一次撤销。
制作来源和推断边界见 [references/sources.md](references/sources.md)。
