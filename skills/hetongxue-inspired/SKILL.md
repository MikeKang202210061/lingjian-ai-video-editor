# 科技实验讲解

采用参考何同学作品制作方法的原创配方。不要宣称作者授权、官方出品或逐镜复刻。

## 分析素材

先列出素材能证明的问题、装置、操作、失败、测量和结果；区分画面事实、转写和推测。
用一个能由现有素材回答的问题组织故事。优先选择操作特写、前后对照、实验过程和结果反应。
保留失败到修正的因果及必要解释。缺少结果时说明缺口，不把不相干镜头拼成成功实验。
抽帧只能证明采样时刻；不要从接触表虚构连续动作或精确对白时间。

## 编排镜头

用问题或有证据的结果片段引入，随后解释目标、展示尝试、给出证据、回收开头。
建议演示镜头约 2–5 秒，复杂解释约 4–8 秒；以语义和真实动作结束为准，不强制套时长。
需要数据时只使用素材中可核实的数值和单位；字幕不能替观众编造实验结论。
在候选 JSON 的 reason 中说明“问题/操作细节/结果/回收”等选择依据，不增加接口未声明的字段。
保留原素材 start/end、来源和顺序约束；不要为了快节奏打断必要因果。

## 安排效果与声音

用干净切点连接操作，在细节或结果处使用小幅推近/强调字幕，每次强调至少间隔 8 秒。
字幕每次强调一个关键信息，保持高对比度；无可靠转写时留空，不能凭风格补台词。
使用清晰的讲解原声和低音量配乐，仅在有意义的结果处加轻提示音。
把复杂图解、物体跟踪、界面替换或三维演示列为待制作项，不把它们写成已完成。
保留真实装置的实拍价值，不把实拍机械运动误归为可一键生成的剪辑特效。

## 执行与审阅

使用 [profile.json](profile.json) 中的受限参数，由灵剪编译本地效果和 Resolve 指令。
本地执行已有字幕强调和运镜；Resolve 当前只映射静态缩放及轻量饱和度，不等同动态关键帧。
禁止输出或运行 Python、Shell、任意 SDK 方法名、下载链接或陌生模板路径。
先展示镜头依据、效果及未映射能力，等待用户应用方案；保持一次撤销可恢复原时间线。
研究出处及证据边界见 [references/sources.md](references/sources.md)。
