# 实验性 DaVinci Resolve 后端

目标是让用户在灵剪描述需求、审阅 AI 计划、发起任务并查看结果，由本机达芬奇承担执行。
当前是**基础剪辑桥接原型**：实现代码、界面和模拟 SDK 检查，不代表已通过真实达芬奇验收。
现有 FFmpeg 导出保持独立可用。

## 当前链路

1. 灵剪已有 AI 分析生成计划，经过现有预览、校验与确认，成为可编辑的时间线。
2. 用户在“音频与导出”展开“达芬奇后端（实验）”，检测本机连接。
3. 适配层从当前时间线生成固定结构的 JSON：本地素材、入出点、顺序和输出尺寸。
4. 独立 Python 子进程载入用户已安装的官方 SDK，建立新工程、导入素材、创建基础剪辑时间线并渲染。
5. 灵剪用 FFmpeg 检查临时 MP4，成功后替换目标；可点击“在灵剪内预览输出”。

用户不需要手写逐条 SDK 命令。模型也不直接提供 Python、Shell 或任意 API 方法名：
它仍使用现有可校验剪辑计划，由固定适配器展开 SDK 调用。

## 本版能力边界

| 已实现的接口路径 | 尚未迁移的内容 |
| --- | --- |
| 检测 SDK、版本和当前工程状态 | 自动安装、购买/激活、完全无人值守启动达芬奇 |
| 素材导入、入出点到源帧映射、顺序拼接 | 字幕、标题、转场、蒙版、运镜、人物效果及 V2+ 叠加 |
| 固定 30 fps 时间线、现有输出尺寸、MP4/H264 能力检查 | 背景音乐、闪避、独立音效及音量/静音调整；目前仅保留原素材自带音轨 |
| 发起渲染、请求取消、检查完成状态、校验后发布 | 任意 Resolve FX、Fusion 节点和关键帧模板的自然语言生成 |
| 灵剪内的独立结果预览窗口 | 真实 Windows/Resolve、GPU、媒体设备、混合帧率/时码和长期稳定性验收 |

发送前明确列出当前工程中不会迁移的能力，必须确认导出“基础版”。
需要保留现有完整效果时，应继续使用本地 FFmpeg 导出，不将基础版伪装成完整工程转换。
首版每次新建独立 `LingJian_<任务ID>` 达芬奇工程，保存但不删除，后续可以在达芬奇查看。

## 电脑上的初始配置

- 需要用户本机已有兼容的 **DaVinci Resolve Studio** 和官方脚本 SDK。本项目不购买、激活或下载付费软件。
- 按安装版说明开启外部脚本 **Local**。首次设置、保存并关闭已有达芬奇工程需要在达芬奇完成。
- 达芬奇需已启动且完全加载；本原型要求其停留在项目管理器，不操作已打开的用户工程。
- 在灵剪选择与 SDK 兼容的本机 Python 解释器；默认使用灵剪当前解释器，但不代表它一定适配用户安装的 SDK。
- SDK 可留空尝试标准位置，或选择 `Developer/Scripting`（也接受其中的 `Modules`）。Windows 标准目录为：

```text
%PROGRAMDATA%\Blackmagic Design\DaVinci Resolve\Support\Developer\Scripting
```

以安装包中 **Help → Documentation → Developer → Scripting/README.txt** 的路径、解释器和版本要求为准。
上方环境变量路径是示意，建议用文件夹选择器选择实际位置；自定义安装的脚本库路径需按该 README 配置。
此版本从源码运行；尚未为独立安装包打包桥接脚本。普通剪辑/本地导出无需启用本模块。

## 任务与文件保护

- 只接受 `probe` 和 `render_basic` 两个操作，拒绝未知字段、任意代码、非有限数值、无效范围和素材覆盖。
- 单窗口内，达芬奇渲染与本地导出互斥；检测/执行期间保留线程，退出或换工程会等待。
- 只有本次调用创建的新工程会被保存/关闭，不删除达芬奇工程；已有工程会阻止执行。
- 在目标旁的唯一任务目录渲染，完成后由灵剪校验再替换目标。失败或取消保留此前输出。
- 取消通过任务标记通知子进程，在接口响应时停止本次独立工程的渲染。SDK 阻塞时不能保证立即取消。
- 无结果、超时或无法确认停止时标为“状态未知”，保留任务目录，要求先检查达芬奇后重新检测连接，不自动重试。
- 未提供跨窗口、跨进程或其他控制达芬奇程序之间的仲裁；执行期间应独占该达芬奇实例。
- 不启动网络服务或要求启用 Network；连接依赖本机官方 SDK。

## 验证证据

- `python tests/run_tests.py`：通过；新增 20 项协议、客户端和 SDK 合同测试。合同对象是模拟器，不是真实达芬奇。
- 包含独立子进程加载显式假 SDK 的检测，以及假 SDK 返回真实生成 MP4 后的校验/发布检查；这些证明进程和文件链路，不证明实际剪辑或特效效果。
- 协议采用 ASCII JSON 消息框架、显式 UTF-8 输入；在 `PYTHONIOENCODING=ascii` 的子进程中验证中文 SDK 路径和中文返回信息，降低 Windows 管道默认编码的影响，但不是 Windows 实机检查。
- Qt 联合回归共 73 项通过：新增 14 项达芬奇界面/状态检查，保留原 59 项；SDK 工作线程被替换为可控测试对象。
- 8 项既有真实 FFmpeg 采样/导出检查通过；程序与新增测试通过编译检查。
- 1366×768、1120×680 离屏检查，包含中文字体；发现横向溢出后已收拢组标题和尺寸策略，并重新确认无横向滚动。
- 当前执行环境没有 `/opt/resolve` 或可连接的达芬奇，**没有真实 SDK/授权/渲染验收，也没有调用付费模型**。

## 依据与后续

- [Blackmagic Studio 官方说明](https://www.blackmagicdesign.com/products/davinciresolve/studio) 列出 Python/Lua 脚本及工作流 API。
- [Blackmagic 20.2 更新说明](https://documents.blackmagicdesign.com/SupportNotes/DaVinci_Resolve_20.2_New_Features_Guide.pdf) 将具体脚本接口文档指向安装包的 Developer 目录。
- 本原型接口合同参考 Blackmagic 随安装包分发的 Scripting README；其
  [公开文本镜像](https://gist.github.com/X-Raym/2f2bf453fc481b9cca624d7ca0e19de8) 不是官方托管站，不能替代用户安装版本的文档和实机验证。
- 当前标准能力检查对不支持的 API/编码器直接报错。源帧映射、时码、混合帧率及 SDK 对参数的解释仍需真实素材实测。

要进一步实现精细包装，需要逐项接入经过验证的 Fusion 模板、变换/关键帧、调色和字幕等受限能力，
并让 AI 选择模板、填写参数与安排时机。调用成熟软件能复用执行能力，但不能保证任意自然语言都能生成优质成片。
本原型不保证达芬奇始终无窗口、不抢焦点或无需首次配置；正常任务尽量在灵剪完成，初始化及异常仍可能需要进入达芬奇。
